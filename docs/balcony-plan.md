# Балконы под ключ: план реализации

Мобильное приложение для фирм и бригад, которые стеклят и отделывают балконы и лоджии: остекление, вынос, обшивка, утепление, отделка внутри, крыша.
Строим в духе нашего приложения для натяжных потолков: тот же стек, дизайн и подход.

Мокапы: `screenshots/balcony/0-overview.png` (исходник `mock.html`).
Соседние планы: `docs/soft-windows-plan.md`, `docs/blinds-plan.md`. Каркас и часть модели общие.

---

## 1. Чем ниша отличается и где ценность

- **Самый высокий чек** (60–250 тыс. за балкон) и **самая дорогая ошибка**: неверная рама, забытый вынос, не учтённый перепад плиты.
- **Один замер даёт три результата:** рамы на производство, материалы на отделку и смету клиенту. Сейчас это три отдельных подсчёта на бумаге и в Excel. Приложение делает их из одних данных.
- **Продажа вариантами:** «просто застеклить» против «тёплый балкон под ключ». Разница в 2–3 раза, и клиенту нужно её показать.
- **Конкуренция:** рамы фирмы уже считают в программах оконных заводов. Мы продаём не «расчёт рам», а **весь балкон одной сметой плюс закупка для бригады**.

Брать эту нишу третьей, когда ядро обкатано на шторах или мягких окнах: здесь больше всего предметной логики.

## 2. Принципы

**Простота**
- Основной путь: Форма → Высоты → Остекление → Отделка → Смета. Каждый шаг — один экран, и пропустить можно любой, кроме формы. Например, без отделки получится смета только на остекление.
- Форма из шаблона: прямой, П, Г, эркер, сапожок. Вводятся только длины сторон, а углы шаблон знает сам.
- Мастер вводит только то, что меряет рулеткой. Всё производное (рамы, углы, площади, материалы) считается само и показывается с пояснением «почему».
- Размеры в миллиметрах, ввод через `NumPad`. Всё работает офлайн.

**Универсальность**
- **Системы остекления — это данные.** ПВХ, алюминий раздвижной, безрамное: у каждой свои ограничения (максимальная ширина и высота рамы и створки), типы створок, цена за м² или за раму, опции. Новый профиль или новый завод добавляются в настройках.
- **Отделка — это «рецепты».** Вариант отделки = работа + материалы с расходом на единицу (м², пог. м, шт). Например, «Панели ПВХ по обрешётке»: панели 1,1 шт/м² (с запасом), брус 2,5 м/м², саморезы… Любую отделку (вагонка, МДФ, покраска, пробка) фирма заводит сама, без кода.
- **Поверхности считаются из геометрии,** а материал на каждую выбирается отдельно. Одна модель работает для балкона, лоджии и эркера.
- Не привязываемся к заводу и поставщику. Заказ рам уходит в PDF или xlsx, закупка — текстовым списком в любой мессенджер.

## 3. Стек и переиспользование

Стек тот же: Ionic React + Capacitor, Konva (план), SVG (развёртка рам, вид изнутри), jsPDF, Vitest, localStorage на старте, SheetJS для xlsx.

| Источник | Что берём |
|---|---|
| ceiling-app: тема, `Dialogs`, `ActionButton`, `NumPad`, `keyboard.ts`, `storage.ts`, `uuid.ts` | как есть |
| ceiling-app: проекты, статусы, фильтры, аванс | как есть |
| ceiling-app: `Summary`, `pricing.ts`, `PriceEditSheet`, PDF и отправка | адаптируем: разделы сметы, варианты |
| ceiling-app: `geometry.ts`, холст | упрощаем: план — ломаная линия парапета вдоль стены дома |
| ceiling-app: «Заказ в цех» | адаптируем под заказ рам |
| ceiling-app: AI-примерка + `worker/` | этап 3: «как будет выглядеть балкон» по фото |
| план штор: модель «Система», варианты, импорт прайсов из Excel | как есть, если к этому моменту сделано |
| план мягких окон: деление длины на полотна | та же идея для деления на рамы |

К третьему приложению общее ядро (проекты, статусы, аванс, смета с вариантами, PDF, справочники) уже должно быть вынесено в общий пакет. Здесь пишем только предметную часть.

## 4. Модель данных

```ts
Project {                         // как в потолках
  id, client, phone, address, floor, floorsTotal, status, advance, pricing
  balcony: Balcony
  variants: Variant[]             // «А — холодное», «Б — под ключ»
}

// ── замер (общий для всех вариантов) ──
Balcony {
  template: 'straight' | 'U' | 'L' | 'bay' | 'boot'
  segments: Segment[]             // ломаная парапета слева направо
  slab: { depth, heights: { at: mm; h: mm }[] }   // высота до плиты в точках
  parapet: { height, kind: 'metal' | 'concrete' | 'brick' | 'none' }
  floorToCeiling
  hasRoofSlab: boolean            // false = последний этаж, нужна крыша
  houseWall: { length, openings: { w, h }[] }     // дверь и окно в квартиру
  photos: string[]; note?
}
Segment { length, angleToNext: deg, extension: mm /* вынос */ }

// ── решения (по вариантам) ──
Variant {
  id, name
  glazing?: { systemId, frames: Frame[]; options: Record<groupId, optionId> }
  finishing: Record<SurfaceId, { recipeId } | null>
  extras: { itemId, qty }[]       // крыша, обшивка снаружи, отливы, электрика, шкаф, демонтаж
}
Frame { segment, index, width, height, type: 'fixed' | 'turn' | 'tiltTurn' | 'slide', mosquito? }

// ── справочник ──
GlazingSystem {
  id, supplierId, kind: 'pvc' | 'alu' | 'frameless'
  limits: { maxFrameW, maxFrameH, maxSashW, maxSashH }
  gaps: { top, bottom, side }     // монтажные зазоры
  corners: { 90: itemId; any: itemId }   // поворотный профиль / угловой соединитель
  price: { model: 'm2' | 'frame' | 'grid'; … }
  frameTypes: ('fixed' | 'turn' | 'tiltTurn' | 'slide')[]
  optionGroups
}
Recipe {                          // вариант отделки
  id, name, surfaces: SurfaceKind[]
  work: { pricePerUnit, unit: 'm2' | 'm' | 'pcs' }   // клиенту и бригаде
  materials: { materialId, perUnit, wastePct }[]
}
Material { id, name, unit: 'pcs' | 'pack' | 'm' | 'm2', size?: { w, l }, coverage?, price, supplierId? }
ExtraItem { id, name, unit, price, workerPrice, autoQty?: 'roofArea' | 'outerArea' | 'sillLen' }
```

## 5. Расчётное ядро (`lib/`, чистые функции + тесты)

| Файл | Что считает |
|---|---|
| `shape.ts` | шаблон → ломаная; координаты старого парапета и новой линии с выносом; площадь плиты и площадь с выносом |
| `heights.ts` | перепад плиты по точкам; высота рам = минимальная высота − зазор; добор там, где выше; предупреждения о перепаде больше N мм и о недостатке точек |
| `frames.ts` | деление каждого сегмента на рамы с учётом максимальной ширины системы и углов; тип угла по градусам; поворотные профили, подставочный профиль, отливы, подоконник (пог. м) |
| `surfaces.ts` | поверхности из геометрии: парапет изнутри, стена дома (минус проёмы), глухие боковины, пол, потолок, откосы; площади и периметры |
| `recipes.ts` | рецепт × площадь → работа и материалы; округление до штук и упаковок по размеру и покрытию |
| `extras.ts` | автоколичества допов: крыша по площади с выносом, обшивка снаружи по парапету, отливы по длине |
| `estimate.ts` | разделы сметы (остекление, вынос и наружные работы, отделка, прочее) для клиента и бригады, по вариантам (общий модуль) |
| `orders.ts` | заказ рам (нумерация, эскизы, профили, сетки); закупочный лист для бригады, сгруппированный по материалам и поставщикам |

Тесты строятся на 3–5 реальных балконах от фирм: замер → рамы → материалы → смета.

## 6. Экраны

Вкладки: **Объекты · Прайс · Кабинет**.

1. **Объекты.** Список, статусы, фильтры. Как в потолках.
2. **Форма** (мокап 1)
   - Чипы шаблонов, план сверху: стена дома, старый парапет пунктиром, новая линия остекления.
   - Тап по стороне открывает NumPad.
   - Ниже вынос (по подоконнику или по плите, мм), тип парапета, нужна ли крыша.
   - Внизу итог по выбранному варианту и кнопка «Смета».
3. **Высоты** (мокап 2)
   - Вид спереди: парапет, проём до плиты, точки замера. Количество точек зависит от длины, минимум три.
   - Поля высот, высота парапета, от пола до потолка, глубина плиты.
   - Предупреждение о перепаде и выбранная высота рам.
4. **Остекление** (мокап 3)
   - Переключатель системы (холодное / тёплое) прямо сверху.
   - Развёртка рам: тап по раме меняет её тип, долгий тап делит или объединяет рамы.
   - Опции списком, внизу м² и ₽.
5. **Отделка** (мокап 4)
   - Схематичный вид изнутри с выносками площадей.
   - Список поверхностей, на каждую рецепт из справочника или «без отделки».
   - Электрика и допы штуками.
   - Внизу материалы и работа.
6. **Смета** (мокап 5)
   - Плашки вариантов, «+ Вариант» копирует текущий.
   - Разделы, вкладки Клиенту / Бригаде, правка цены, скидка, аванс.
   - PDF: варианты рядом, план и развёртка рам на первой странице.
7. **Заказ** (мокап 6). Шторка: «Рамы в цех» (PDF или xlsx с эскизами) и «Материалы бригаде» (поделиться текстом или PDF).
8. **Прайс.** Системы остекления, рецепты отделки, материалы, допы, расценки бригады. Пресет «типовая балконная фирма». Импорт цен из Excel.
9. **Кабинет.** Профиль фирмы, зазоры и допуски по умолчанию, статистика.

## 7. Этапы

### Этап 0. Проверка (1–2 недели, до кода)
- Показать мокапы 5–10 балконным фирмам.
- Собрать: максимальные размеры рам и створок, монтажные зазоры, как делают вынос (до скольки мм), чем считают рамы сейчас (программа завода, свой Excel), прайсы, типовые варианты отделки с расходами, 3–5 реальных объектов «замер → заказ → смета».
- Узнать: свои ли рамы или с завода; какая доля выручки приходится на отделку; кто платит за софт и сколько замерщиков.

### Этап 1. MVP «замер → остекление → смета» (4–5 недель)
- Каркас на общем ядре.
- Шаблоны: прямой, П, Г (углы 90°). `shape.ts`, `heights.ts`, `frames.ts` с тестами.
- Экраны «Форма», «Высоты», «Остекление» с системами ПВХ и алюминий из пресета.
- Смета с двумя вариантами и PDF.
- **Критерий готовности:** замерщик на объекте выдаёт смету на остекление в двух вариантах до ухода от клиента.

### Этап 2. Отделка и заказы (3–4 недели)
- `surfaces.ts`, `recipes.ts`, `extras.ts`. Экран «Отделка», справочник рецептов и материалов.
- Заказ рам в PDF и xlsx, закупочный лист бригаде, вкладка «Бригаде».
- Наружные работы: обшивка, отливы, вынос с усилением.
- **Критерий готовности:** бригада фирмы-пилота закупает материалы строго по листу из приложения, без дозакупок.

### Этап 3. Сложные формы и продажи (3 недели)
- Эркер и сапожок (произвольные углы, угловые соединители), крыша на последнем этаже.
- Фото в смете.
- AI-визуализация: тёплый балкон по фото клиента (`worker/`).
- Безрамное остекление новым пресетом.

### Этап 4. Деньги и команда (после пилота)
- Подписка через RuStore и Google Play. Бесплатно: до 3 объектов в месяц и PDF с водяным знаком.
- Тариф «Фирма»: бэкенд, синхронизация, роли (замерщик, бригадир, владелец). Себестоимость и наценка видны только владельцу.
- Прайсы заводов «из облака», как в плане штор: только если пилот покажет, что это главная боль.

Сроки ориентировочные, на одного разработчика с Claude, при уже вынесенном общем ядре. Без ядра добавить 2–3 недели на каркас.

## 8. Чего сознательно не делаем

- Не конструируем окна заново, как программы заводов: армирование, расчёт ветровой нагрузки, раскрой профиля. Рама для нас — это размер, тип и цена.
- Не делаем 3D-модель балкона: хватает схемы изнутри и AI-визуализации.
- Не ведём CRM, склад и остатки.
- Не занимаемся согласованиями выноса с УК и законностью: только справка в «Справочнике».
- Не интегрируемся с программами заводов на старте, только PDF и xlsx.

## 9. Открытые вопросы (закрыть на этапе 0)

- Максимальная ширина рамы и створки у ходовых систем, стандартные монтажные зазоры.
- Вынос: по подоконнику или по плите, максимум, как считают цену (за пог. м?).
- Как цена рам приходит от завода: за м², за раму, по сетке? Можно ли импортировать прайс?
- Обшивка снаружи и крыша: по каким правилам считают площадь и материалы?
- Типовые рецепты отделки и реальные расходы (брус на м², запас на подрезку панелей).
- Нужны ли отдельные «шкаф» и «мебель» на балкон, или это штучные допы?
- Как бригаде удобнее получать закупку: текст в мессенджер, PDF, список по магазинам?
