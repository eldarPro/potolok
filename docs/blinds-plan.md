# Шторы, жалюзи, рольставни: план реализации

Мобильное приложение для салонов и мастеров, которые продают и монтируют рулонные шторы, зебру, жалюзи, плиссе, рольставни и москитные сетки.
Строим в духе нашего приложения для натяжных потолков: тот же стек, дизайн и подход.

Мокапы: `screenshots/blinds/0-overview.png` (исходник `mock.html`).
Соседний план: `docs/soft-windows-plan.md`. Каркас общий, отличается предметная часть.

---

## 1. Чем ниша отличается и где ценность

- **Салон — дилер, а не производитель.** Изделия шьют фабрики, салон замеряет, продаёт и монтирует. Раскроя и цеха нет. Ценность в том, чтобы:
  1. не ошибиться в замере и ограничениях системы (не та система для створки, короб не влез в откос);
  2. быстро посчитать цену по прайс-сеткам разных фабрик;
  3. без ошибок перевести замер в бланк каждой фабрики с её вычетами;
  4. продать дороже: варианты в смете, подсказки по допродаже, AI-примерка.
- **На объекте много позиций** (10–20), у каждой 4–6 опций. На бумаге именно здесь больше всего путаницы.
- **Деньги:** рольставня на гараж стоит 60–80 тыс. Одна ошибка в коробе или профиле обходится дороже годовой подписки.

## 2. Принципы

**Простота**
- Основной путь: Объект → Окно → Изделие → Смета. Заказ поставщикам делается одной кнопкой из сметы.
- **Один конфигуратор на все типы изделий.** Набор полей задаёт тип системы, поэтому отдельного экрана «рольставни» нет: для рольставни в том же экране появляется блок подбора.
- Размеры в миллиметрах, ввод через `NumPad`. Кнопки «Копировать на все створки» и «Как у предыдущего окна».
- Из коробки идут пресеты популярных систем: можно начать работать, ничего не настраивая.
- Всё работает офлайн.

**Универсальность**
- **Система — это данные, а не код.** Любое изделие (штора, жалюзи, рольставня, сетка, даже карниз) описывается одной сущностью «Система»:
  - что мерить: створку, стекло или проём;
  - ограничения;
  - модель цены;
  - группы опций;
  - правила пересчёта в бланк фабрики.

  Новая фабрика или новый продукт добавляются через настройки, без релиза.
- Не привязываемся к фабрикам. Поставщики, ткани и прайсы заводит пользователь сам: руками или импортом из Excel.
- Правила вычетов простые: «база ± мм, округлить до N». Никакого языка формул. Это покрывает почти все бланки и понятно мастеру.
- Таблицы подбора рольставен (профиль, короб, привод) — редактируемые справочники с пресетом, а не зашитая логика.

## 3. Стек и переиспользование

Стек тот же: Ionic React + Capacitor, Konva (эскиз окна), jsPDF, Vitest, localStorage на старте. Для импорта прайсов добавляем SheetJS (`xlsx`).

| Модуль ceiling-app | Что делаем |
|---|---|
| тема, шрифты, `Dialogs`, `ActionButton`, `NumPad`, `keyboard.ts` | как есть |
| `storage.ts`, `uuid.ts` | как есть, свои ключи и миграции |
| `ProjectList`, `ProjectFilterSheet`, `ProjectStatus`, `projectStatus.ts` | как есть |
| `AdvanceSheet`, `advance.ts` | как есть |
| `Summary` (Клиенту / Бригаде), `PriceEditSheet`, `estimateFormat.ts`, `pricing.ts` | адаптируем, добавляем варианты |
| `estimatePdf.ts`, `workshopPdf.ts`, `sharePdf.ts` | адаптируем: смета с вариантами, бланки поставщикам |
| `PriceList`, `Cabinet`, `Profile`, `Statistics`, `Handbook` | адаптируем: поставщики, системы, ткани |
| `Fittings` / AI-примерка + `worker/` | этап 3: штора на фото окна клиента |
| холст, геометрия потолка, ниши, свет, усадка, three.js | не нужны, эскиз окна рисуем проще |

Если делаем и мягкие окна, и шторы: первое приложение — копия ceiling-app. На втором выносим общее ядро (проекты, статусы, аванс, смета, PDF, NumPad, тема) в общий пакет.

## 4. Модель данных

```ts
Project {                         // как в потолках
  id, client, phone, address, status, advance, pricing, createdAt
  rooms: Room[]
  variants: Variant[]             // минимум один, «Основной»
}

Room   { id, name, windows: Window[] }        // «Гостиная», «Гараж»

Window {                          // окно / дверь / проём — замер общий для всех вариантов
  id, name, kind: 'window' | 'door' | 'opening'
  sashes: Sash[]                  // для окна/двери
  opening?: { w, h, revealDepth, sill? }      // для проёма (рольставни, вертикальные)
  photos: string[]; note?
}
Sash { width, height, type: 'fixed' | 'turn' | 'tiltTurn', glassW?, glassH?, beadDepth?, handle?: 'left' | 'right' }

Variant { id, name, products: Product[] }     // «А — ремень», «Б — электро»
Product {
  id, windowId, sash?: number     // null = на весь проём
  systemId, fabricId?, options: Record<groupId, optionId>
  qty, priceOverride?
}

// ── справочник ──
Supplier { id, name, contacts, orderFormat: 'pdf' | 'xlsx', blankTemplate? }
System {
  id, supplierId, type: 'roller' | 'zebra' | 'pleated' | 'venetian' | 'vertical' | 'shutter' | 'mosquito'
  base: 'sash' | 'glass' | 'opening'          // что мерить
  limits: { minW, maxW, minH, maxH, maxArea?, minBead? }
  price: { model: 'grid' | 'm2' | 'pcs'; grids?: Record<category, Grid>; perM2?; perPcs? }
  optionGroups: { id, name, options: { id, name, price?, required? }[] }[]
  orderRules: { width: Rule; height: Rule }   // Rule = { from: 'measure' | 'glass' | 'sash'; offset: mm; round?: mm }
  hints?: { when, text, upsellSystemId? }[]   // «глухая створка → UNI»
}
Grid   { widths: mm[]; heights: mm[]; prices: number[][] }   // «до 600 × до 1600»
Fabric { id, supplierId, collection, name, color, category, tags: ('blackout' | 'dimout' | 'zebra')[], maxW? }
ShutterTables {                    // редактируемый пресет
  profiles: { id, name, maxW, maxArea, kgPerM2, rollDiam }[]
  boxes:    { size, maxRollLen }[]
  drives:   { torque, maxKg, price }[]
  manualMaxArea                    // ручное управление выше — предупреждение
}
WorkRates { perProductType, departure, … }    // вкладка «Бригаде»
```

## 5. Расчётное ядро (`lib/`, чистые функции + тесты)

| Файл | Что считает |
|---|---|
| `limits.ts` | проверка изделия по ограничениям системы и ткани: ширина, высота, площадь, штапик, максимальная ширина ткани. Возвращает ошибки и предупреждения с текстом для мастера |
| `price.ts` | цена по сетке (округление вверх до ближайшей колонки и строки «до N»), за м² или за штуку, плюс опции, плюс наценка салона |
| `hints.ts` | подсказки и допродажа по правилам системы (глухая створка → UNI, южная сторона → блэкаут) |
| `shutter.ts` | подбор для рольставни: профиль по ширине и площади, длина рулона → короб, вес → привод, монтаж в проём или накладной по глубине откоса |
| `orderRules.ts` | пересчёт замера в размеры бланка по правилам поставщика |
| `variants.ts` | копирование варианта, разница между вариантами, итог по каждому |
| `estimate.ts` | смета клиенту и бригаде по варианту (поверх `pricing.ts`), скидка, аванс |
| `supplierOrders.ts` | группировка по поставщикам, строки бланка, сводка; выгрузка в PDF или xlsx |
| `importGrid.ts` | импорт прайс-сетки из xlsx/csv: определение осей ширина × высота, предпросмотр, проверка дыр |

Тесты строятся на реальных прайсах и бланках 2–3 фабрик (см. этап 0).

## 6. Экраны

Вкладки: **Объекты · Прайс · Кабинет**. Вкладка «Примерка» появится на этапе 3.

1. **Объекты.** Список, статусы, фильтры. Как в потолках.
2. **Объект** (мокап 1)
   - Помещения, в них окна с мини-эскизом и подписью изделий.
   - «Не замерено» выделено цветом.
   - Внизу «N изделий · ₽» и кнопка «Смета».
   - «+ Помещение», «+ Окно», свайп: копировать или удалить.
3. **Окно** (мокап 2)
   - Эскиз: число створок, тип каждой (глухая, поворотная, поворотно-откидная), сторона ручки. Тап по створке выбирает её.
   - Размеры створки, стекла и глубина штапика. Какие поля нужны, видно по выбранной системе.
   - Зелёная плашка «система подходит» или красная «не подходит, почему».
   - Подсказки допродажи.
   - «Копировать на все створки», «Изделие →».
   - Для проёма (рольставни, вертикальные): ширина, высота, глубина откоса, есть ли розетка.
4. **Изделие** (мокапы 3 и 4, один экран)
   - Система (чипы), ткань из каталога (плитки с цветом и категорией, поиск, фильтр «блэкаут»), группы опций.
   - Цена с подсвеченной ячейкой прайс-сетки, чтобы мастер доверял цифре.
   - Для рольставни вместо ткани блок подбора: профиль, короб, вес полотна, привод, монтаж. Каждое решение с пояснением «почему».
5. **Смета** (мокап 5)
   - Плашки вариантов сверху, «+ Вариант» копирует текущий.
   - Вкладки Клиенту / Бригаде, правка цены, скидка, аванс.
   - PDF: все варианты рядом или только выбранный.
6. **Заказы поставщикам** (мокап 6). Шторка из сметы: карточки по поставщикам, у каждой строки «замер → размер в бланк», под карточкой правило фабрики. Отправка PDF или Excel.
7. **Прайс.** Поставщики → системы → ткани. Импорт сетки из Excel с предпросмотром. Пресеты систем. Таблицы рольставен.
8. **Кабинет.** Профиль салона (логотип и реквизиты в PDF), наценка по умолчанию, расценки бригады, статистика.

## 7. Этапы

### Этап 0. Проверка (1–2 недели, до кода)
- Показать мокапы 5–10 салонам и мастерам.
- **Собрать у 2–3 фабрик:** прайс-сетки (в каком виде присылают), бланки заказа, правила вычетов, ограничения систем. Без этого ядро не написать.
- Узнать: сколько фабрик у салона, как сейчас отправляют заказ (бланк, портал фабрики, мессенджер), сколько ошибок в месяц, есть ли свой монтаж, кто платит за софт.

### Этап 1. MVP «замер → смета» (4 недели)
- Каркас из ceiling-app: тема, вкладки, проекты, статусы, аванс.
- Помещения → окна → створки, эскиз окна.
- Справочник: поставщики, системы из пресетов (рулонные Мини/UNI, зебра, горизонтальные жалюзи), ткани, ручной ввод сетки.
- Конфигуратор, `limits.ts`, `price.ts`.
- Смета клиенту + PDF + отправка.
- **Критерий готовности:** замерщик на реальной квартире собирает смету быстрее, чем по папке с прайсами.

### Этап 2. Фабрики и рольставни (3–4 недели)
- `orderRules.ts`, `supplierOrders.ts`: заказы поставщикам, PDF и xlsx.
- `importGrid.ts`: импорт сетки из Excel.
- Рольставни: `shutter.ts`, таблицы, блок подбора.
- Варианты в смете, вкладка «Бригаде».
- `hints.ts`: подсказки и допродажа.
- **Критерий готовности:** салон-пилот неделю отправляет заказы на фабрику только из приложения, и ни одна фабрика не перезвонила с вопросом.

### Этап 3. Продажи (2–3 недели)
- AI-примерка: выбранная ткань на фото окна клиента (готовый `worker/`).
- Фото окон в смете.
- Плиссе, вертикальные жалюзи, москитные сетки — новыми пресетами систем, без нового кода.
- Ткани с фото-текстурами в каталоге.

### Этап 4. Деньги и команда (после пилота)
- Подписка через RuStore и Google Play. Бесплатно: до 3 объектов в месяц и PDF с водяным знаком.
- **Тариф «Салон»** (владелец + замерщики): бэкенд, синхронизация, роли. У замерщика скрыты закупочные цены и наценка.
- **Перспектива B2B:** фабрики публикуют свои системы, ткани и прайсы в общий каталог, и у всех салонов они обновляются сами. Отсюда два возможных шага: приём заказов от салонов и плата фабрики за размещение. Делаем, только если пилот покажет, что ручное ведение прайсов — главная боль.

Сроки ориентировочные, на одного разработчика с Claude. Самая трудоёмкая часть — модель «Система», конфигуратор и импорт прайсов, а не экраны.

## 8. Чего сознательно не делаем

- Не делаем CRM, телефонию, задачи.
- Не интегрируемся с API и порталами фабрик на старте, только PDF и xlsx.
- Не ведём склад и остатки.
- Не делаем 3D и AR: хватает AI-примерки на фото.
- Не пишем формульный движок для правил, только «база ± мм, округление».
- Не локализуем на старте, только русский, инфраструктуру i18n оставляем.

## 9. Открытые вопросы (закрыть на этапе 0)

- В каком виде фабрики дают прайсы: Excel-сетка, PDF, портал? Как часто меняются цены?
- Типичные правила вычетов: по ткани, по габариту, по стеклу. Хватит ли «база ± мм» или встречаются проценты и условия?
- Как фабрики хотят получать заказ: свой бланк (точный шаблон), любой PDF, Excel?
- Рольставни: заказ по проёму или по габариту? Кто выбирает привод: салон или завод? Какие таблицы подбора у заводов?
- Ставит ли салон сам или есть монтажники на сдельной оплате (нужна вкладка «Бригаде»)?
- Нужен ли учёт закупочной цены и маржи по каждому изделию?
- Насколько важны москитные сетки и плиссе для старта?
