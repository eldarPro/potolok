# Мягкие окна: план реализации

Мобильное приложение для замерщиков и фирм, которые делают мягкие окна (ПВХ-шторы для беседок, веранд, террас, летних кафе).
Строим в духе нашего приложения для натяжных потолков: тот же стек, дизайн и подход.

Мокапы: `screenshots/soft-windows/0-overview.png` (исходник `mock.html`).

---

## 1. Принципы

**Простота**
- Путь «замер → смета → цех» проходится за 3 экрана: Объект → Проём → Смета. Всё остальное открывается шторками поверх.
- Минимум ввода. Размеры вводятся своей цифровой клавиатурой (`NumPad`), опции изделия по умолчанию берутся из настроек, кнопка «Как у предыдущего» копирует параметры с прошлого проёма.
- План беседки необязателен. Можно просто добавлять проёмы списком, а план нарисовать, если хочется.
- Всё работает офлайн: дача, поле, плохая связь.

**Универсальность**
- Не привязываемся к одной фабрике или поставщику. Плёнки, окантовки, крепления и цены человек задаёт сам, а из коробки идёт разумный набор.
- Все технологические допуски вынесены в настройки: нахлёст на брус, окантовка по сторонам, шаг люверсов, ширина рулона, перемычка. В коде нет «магических» 10 и 20 см.
- Любая форма проёма: прямоугольник, трапеция, позже арка. Форма определяется по замерам, а не выбирается заранее.
- Одно приложение подходит и одиночке (замерил, посчитал, отправил), и фирме со своим цехом (заказ в цех, раскрой, остатки).

## 2. Стек и что берём из приложения для потолков

Стек тот же: Ionic React + Capacitor, Konva (план), jsPDF (документы), Vitest (логика), localStorage на старте.

Решение: **новый репозиторий, модули копируем из ceiling-app**. Общий пакет «ядро» выносим, только когда оба приложения устоятся. Раньше это преждевременная платформа.

| Модуль ceiling-app | Что делаем |
|---|---|
| `theme/variables.css`, шрифты, `Dialogs`, `ActionButton` | копируем как есть |
| `NumPad`, `lib/keyboard.ts` | как есть |
| `lib/storage.ts`, `lib/uuid.ts` | как есть, меняем ключи и миграции |
| `ProjectList`, `ProjectFilterSheet`, `ProjectStatus`, `lib/projectStatus.ts` | как есть: статусы Согласование / В работе / Завершён / Отменён |
| `AdvanceSheet`, `lib/advance.ts` | как есть |
| `Summary` (вкладки Клиенту / Бригаде), `lib/estimateFormat.ts`, `PriceEditSheet` | адаптируем: позиции сметы — изделия вместо комнат |
| `lib/pricing.ts` | адаптируем: структура (overrides, скидка, доп. строки) та же, состав позиций новый |
| `lib/estimatePdf.ts`, `lib/workshopPdf.ts`, `lib/sharePdf.ts` | адаптируем шаблоны, отправка та же |
| `PriceList`, `Cabinet`, `Profile`, `Statistics`, `Handbook` | адаптируем справочники |
| `CeilingCanvas`, `lib/geometry.ts`, `lib/roomEdit.ts` | упрощаем до плана беседки: стороны = проёмы |
| `Fittings` / AI-примерка + `worker/` | этап 3: «шторы на фото беседки» |
| `lib/fabric.ts`, `lib/shrink.ts`, ниши, свет, three.js | не нужны |

## 3. Модель данных

```ts
Project {                       // как в потолках
  id, client, phone, address, status, advance, pricing, createdAt
  structure?: Structure         // план (необязателен)
  openings: Opening[]
}

Structure {                     // план сверху
  template: 'rect' | 'hex' | 'free'
  points: Point[]               // контур, см
  posts: Point[]                // столбы — делят стороны на проёмы
}

Opening {
  id, n, name                   // «2 · Фронт правый»
  side?: { edge: number; from: number; to: number }  // привязка к плану
  m: {                          // замер, см; заполняется что есть
    wTop, wBottom, hLeft, hCenter?, hRight, diag?
  }
  shape: 'auto' | 'rect' | 'trapezoid'   // auto = по замерам
  product: ProductOptions
  photos: string[]
  note?: string
}

ProductOptions {
  filmId, edgingId, fasteningId
  edging: { top, bottom, left, right }   // см, по умолчанию из настроек
  overlap: number                        // нахлёст на брус, см на сторону
  step: number                           // шаг крепления, см
  zipper?: 'none' | 'center' | 'side'
  rollUp: number                         // ремешки скатки, шт
}

Catalog (справочник, правит пользователь) {
  films:      { id, name, thickness, tint, rollWidth, pricePerM2, costPerM }
  edgings:    { id, name, color, pricePerM }
  fastenings: { id, kind: 'swivel' | 'strap' | 'french' | 'zip', pricePerPcs }
  extras:     { id, name, unit, price }  // молния, ремешок, доставка…
  workRates:  монтаж ₽/м², выезд…        // вкладка «Бригаде»
}

Settings { defaults: ProductOptions; skewThreshold: 2 /* см */ }
Offcuts  { id, filmId, w, l, fromProjectId }  // склад обрезков
```

## 4. Расчётное ядро (`lib/`, чистые функции + тесты)

Вся предметная логика лежит в чистых функциях с юнит-тестами, как сейчас `shrink.ts` и `pricing.ts`. UI только вызывает их.

| Файл | Что считает |
|---|---|
| `opening.ts` | форма по замерам: перекос > `skewThreshold` даёт трапецию; проверка полноты замера; предупреждения («одна высота — перекос не проверен», «диагональ не сходится с шириной и высотой на N см») |
| `product.ts` | размер изделия = проём + нахлёст; площадь; периметр → окантовка, пог. м; число люверсов и скоб по шагу |
| `panels.ts` | размер плёнки = изделие − окантовка; деление на полотна, если шире рулона: число полотен и перемычек, ширина полотна |
| `cutting.ts` | раскрой полотен на рулоне: жадная укладка «первый подходящий, по убыванию», узкие полотна парами в ширину рулона; итог: длина с рулона, отход %, обрезки |
| `estimate.ts` | позиции сметы клиенту и бригаде из изделий + доп. строки, скидка, аванс (переиспользуем `pricing.ts`) |
| `workshop.ts` | данные для PDF в цех: по каждому изделию эскиз, размеры плёнки, окантовка, фурнитура; сводка материалов |

Тесты пишутся на реальных примерах от мастеров (см. п. 8): «проём такой-то → плёнка такая-то, люверсов столько».

## 5. Экраны

Нижние вкладки как в потолках: **Объекты · Прайс · Кабинет**. Вкладка «Примерка» появится на этапе 3.

1. **Объекты.** Список со статусами, фильтрами и поиском. Один в один с потолками.
2. **Новый объект.** Клиент, телефон, адрес, затем сразу экран объекта. План не спрашиваем.
3. **Объект** (мокап 1)
   - Сверху план, если есть, иначе кнопка «Нарисовать план».
   - Ниже список проёмов: номер, размеры, м², плашки «трапеция» и «молния», статус «замерен / не замерен».
   - Внизу «N проёмов · м² · ₽» и кнопка «Смета». Чип аванса и статус как сейчас.
   - «+ Проём», свайп по проёму: копировать или удалить.
4. **Проём** (мокапы 2+3 на одном экране, две вкладки «Замер» и «Изделие»)
   - Замер: схема проёма с размерами на сторонах, тап по размеру открывает NumPad, точки идут по порядку. Предупреждение о перекосе и выбор «Трапецией / Прямоугольник по меньшему».
   - Изделие: превью с окантовкой и люверсами, опции списком. Каждая опция — шторка с вариантами из справочника.
   - Внизу м², цена и кнопка «Следующий проём →».
   - Фото проёма с камеры.
5. **План беседки.** Шаблоны «прямоугольник» и «шестигранник», произвольный контур, столбы. Тап по стороне между столбами делает её проёмом с тем же номером, что в списке.
6. **Смета** (мокап 4). Вкладки Клиенту / Бригаде, правка цены проекта, скидка, аванс, PDF, «Отправить».
7. **Заказ в цех** (мокапы 5+6). Шторка: сводка материалов, карточки изделий, вкладка «Раскрой». PDF в цех: страница сводки, по странице на изделие, страница раскроя.
8. **Прайс.** Справочники плёнок, окантовок, креплений, допов, расценок бригады. Пресет «стандартный набор».
9. **Кабинет.** Профиль фирмы (логотип и реквизиты в PDF), настройки допусков по умолчанию, статистика, остатки плёнки.

## 6. Этапы

### Этап 0. Проверка (1 неделя, до кода)
- Показать мокапы 5–10 фирмам (Авито, 2ГИС, местные группы ВК и Telegram).
- Собрать: реальные допуски и правила раскроя, 3–5 замеров с итоговыми заказами в цех (это будущие тесты), сколько переделок в сезон, сколько замерщиков, готовность платить.
- Итог этапа: делаем или нет, плюс уточнённый список настроек.

### Этап 1. MVP «замер → смета» (3–4 недели)
- Каркас из ceiling-app: тема, вкладки, проекты, статусы, аванс, хранилище.
- Справочник с пресетом, настройки допусков.
- Проём: замер с NumPad, авто-трапеция, предупреждения, опции изделия, «как у предыдущего».
- `opening.ts`, `product.ts`, `estimate.ts` с тестами.
- Смета клиенту + PDF + отправка.
- **Критерий готовности:** замерщик на реальной беседке быстрее, чем на бумаге, отдаёт клиенту PDF со сметой.

### Этап 2. Цех (2–3 недели)
- `panels.ts`, `cutting.ts`, `workshop.ts` с тестами на примерах фирм.
- Заказ в цех: сводка, карточки, раскрой, PDF.
- Остатки плёнки: учёт и подсказка «есть подходящий обрезок».
- Вкладка «Бригаде» в смете.
- **Критерий готовности:** швея фирмы-пилота шьёт по нашему PDF без звонка замерщику.

### Этап 3. Удобства (2–3 недели)
- План беседки (упрощённый холст).
- Фото проёмов, фото в PDF.
- AI-примерка: шторы с окантовкой выбранного цвета на фото беседки (готовый `worker/`).
- Арочные проёмы, двери на молнии с разметкой молнии в цех.

### Этап 4. Деньги и команда (после пилота)
- Подписка через RuStore Billing и Google Play. Бесплатно: до 3 объектов в месяц и PDF с водяным знаком. Pro: без ограничений.
- **Тариф «Фирма»** (владелец + замерщики): нужен бэкенд с синхронизацией и ролями. Владелец видит все замеры и цены, у замерщика скрыта себестоимость. Это первое место, где без сервера не обойтись. До этого всё локально.
- Сезонный тариф (март–октябрь).

Сроки ориентировочные, на одного разработчика с Claude. Общий каркас уже есть, поэтому основное время уйдёт на расчётное ядро и PDF.

## 7. Чего сознательно не делаем

- Не делаем CRM: воронку, звонки, задачи. Для этого есть Битрикс и amo, у нас только объекты и статусы.
- Не делаем склад и закупки, кроме обрезков плёнки.
- Не делаем 3D и AR: AI-примерки на фото достаточно.
- Не интегрируемся с фабриками на старте, только PDF и «Отправить».
- Не локализуем на старте: только русский, но i18n-инфраструктуру оставляем, как в потолках.

## 8. Открытые вопросы (закрыть на этапе 0)

- Стандартные допуски: нахлёст на брус, окантовка по сторонам, нижняя «юбка». Различаются ли они по креплению?
- Ширины рулонов в ходу (1,4 / 1,5 / 1,6 м?) и правила стыка: перемычка из ткани или сварка внахлёст.
- Как шьют трапецию и арку, какие размеры нужны цеху.
- Зимний монтаж: делают ли поправку на сжатие плёнки на холоде (аналог нашей усадки)?
- Чем считают цену: ₽/м² изделия или отдельно плёнка + окантовка + фурнитура + работа. Возможно, нужны оба режима.
- Как сейчас передают заказ в цех (бумага, WhatsApp-фото, Excel) и кто платит за софт.
