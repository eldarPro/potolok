# ceiling-app

Мобильное приложение для замерщиков и монтажников натяжных потолков: чертёж комнаты → смета клиенту и бригаде → заказ в цех.
Это первое приложение из линейки «замер → смета → производство». Следующие ниши описаны в `docs/*-plan.md` (мягкие окна, шторы и рольставни, балконы), и всё, что ниже, относится и к ним.

**Общение с пользователем — только на русском.**

## Команды

```bash
npm run dev                      # vite; для проверок: npm run dev -- --port 5199 --strictPort
npx tsc --noEmit                 # типы
npx vitest run                   # юнит-тесты (src/lib/*.test.ts)
npx vitest run src/lib/shrink    # один файл
npm run build                    # tsc + vite build (base '/potolok/' в проде)
npx cap sync android             # после build, для APK
```

Бэкенда нет: всё хранится в `localStorage` (ключи `ceiling_*`, `app_lang`). `worker/` — Cloudflare Worker для AI-визуализации, деплоится отдельно (`wrangler deploy`).

## Стек и структура

Ionic 8 + React 19 + TypeScript + Vite + Capacitor 8; Konva (чертёж), three.js (рендер полотна), jsPDF (документы), Vitest.

| Путь | Что там |
|---|---|
| `src/types/index.ts` | все типы данных |
| `src/lib/` | **вся предметная логика**: чистые функции с тестами рядом (`*.test.ts`) |
| `src/lib/storage.ts` | CRUD и миграции localStorage. Меняешь формат — добавь миграцию |
| `src/lib/pricing.ts` | единый расчёт сметы (клиент / бригада, цены проекта поверх ценника) |
| `src/lib/*Pdf.ts`, `sharePdf.ts` | PDF и отправка |
| `src/components/` | переиспользуемые куски UI: шторки, NumPad, карточки |
| `src/pages/` | экраны; вкладки в `Tabs.tsx`: Проекты · Примерка · Ценники · Кабинет |
| `src/locales/*.ts` | 8 языков (ru, en, uk, pl, de, fr, es, tr) |
| `screenshots/<тема>/` | мокапы и проверочные скриншоты по задачам |
| `docs/` | планы будущих приложений |

## Принципы продукта

1. **Простота.** Минимум экранов и переходов. Всё, что можно, делается шторкой снизу поверх текущего экрана, без отдельной страницы. Разумные значения по умолчанию, «как у предыдущего».
2. **Универсальность.** Не привязываемся к конкретному поставщику, цеху или фабрике. Материалы, цены и технологические допуски — это данные в справочниках и настройках, а не константы в коде.
3. **Мастер вводит только то, что меряет рулеткой.** Всё производное (площади, углы, раскрой, материалы) считается само и показывается с пояснением «почему».
4. **Работает офлайн, на телефоне, одной рукой.** Сначала телефон (ширина около 390–420 px), крупные цели для тапа.
5. **Деньги видны сразу.** Итог в рублях всегда виден внизу экрана проекта.

## UI-конвенции (соблюдать в новых экранах)

- **Цвета** — токены из `src/theme/variables.css`: primary `#1E88E5`, фон `#F7F8FA`, карточки белые с радиусом 16, сторона бригады — зелёная `--color-worker` (`#11635F`), изменённая цена проекта — янтарная `--color-changed`. Новые цвета не вводить без причины.
- **Шторка снизу** (`IonModal` с `breakpoints={[0, 1]}`) — основной способ правки чего угодно. Новые разделы комнаты — телом в `SectionPanel`, а не страницей.
- **Числа размеров вводятся только через `NumInput` / `NumPad`** (`src/components/NumPad.tsx`). Клавиатура лежит поверх приложения и ничего не сжимает. Системная клавиатура — только для текста, цен и процентов.
- **Статусы проекта:** Согласование (по умолчанию) / В работе / Завершён / Отменён. Плашка в шапке, смена — листом или свайпом. Цвета в `lib/projectStatus.ts`.
- **Смета:** один экран с переключателем «Клиенту / Бригаде». У клиента не видно цифр бригады. У каждой вкладки свой PDF. Цены проекта переопределяют ценник только для этого проекта.
- **Аванс:** чип справа от статуса → шторка. В смете показывается строками «Аванс −X» и «Осталось к оплате».
- **Действия над элементом чертежа** — карточка снизу (`ElementCard`), геометрия правок — в `lib/roomEdit.ts`.
- **Свайп по строке списка** даёт быстрые действия (статус, аванс, удалить).
- **Опасные действия** — через `useConfirm()` из `Dialogs.tsx`, а не `window.confirm`.

## Как писать код

- Предметная логика — только в `src/lib/` чистыми функциями. Компоненты вызывают их и рисуют. К новой функции расчёта сразу пишем тест в соседнем `*.test.ts`.
- Новый текст в интерфейсе — через `t('раздел.ключ')` из `useT()`, и ключ добавляется **во все 8 файлов `src/locales/`**. Русский пишется первым, остальные переводятся.
- Тексты интерфейса короткие и на языке мастера: «Заказ в цех», «Бригаде», «Осталось к оплате», а не канцелярит.
- Комментарии в коде — по-английски, коротко, только там, где неочевидно «почему».
- Формат хранимых данных меняется только с миграцией в `storage.ts`: у пользователей уже лежат старые проекты.

## Процесс

- **Новая фича или спорный UI:** сначала 2–4 варианта мокапами (скилл `/mockup`), пользователь выбирает, потом реализуем. Отклонённые варианты не возвращаем без запроса.
- **Проверка в рантайме:** скилл `/verify` (Playwright, тестовые данные через localStorage, скриншоты в `screenshots/<тема>/`).
- Перед тем как сказать «готово»: `npx tsc --noEmit` и `npx vitest run` проходят.
- «Посмотри скрин» — значит самый свежий файл в `~/Изображения/Снимки экрана/`.
- **Git:** коммитить только по просьбе. Сообщение коммита — по-русски и по сути («Смета: аванс строкой в PDF»), а не «fix».
